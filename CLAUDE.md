# AGENTS.md

## Repo shape

- This is not a root npm workspace: the root has no `package.json`; run frontend npm commands from `frontend/`.
- `frontend/` is the live UI: Next.js 16 App Router, React 19, TypeScript, Tailwind CSS 4, and mock data.
- `backend/` is a separate FastAPI service. Entry point: `backend/app/main.py`; optimizer modules: `backend/app/optimizer/`; Gemini helpers/fallbacks: `backend/ai/`.
- `frontend/src/app/` contains route files; most UI and interaction logic lives in `frontend/src/components/`.
- The current frontend demo reads typed data from `frontend/src/data/mock-data.ts`; it does not require the backend or frontend env vars unless you explicitly wire API calls.
- `docs/branding.md` and `docs/ui_ux.md` are the UI/product direction. `Greenmile_PRD_v2.md` is older planning context; verify its claims against code before using them.

## Commands

- Frontend install: `cd frontend && npm install` (`frontend/package-lock.json` is the npm lockfile).
- Frontend dev server: `cd frontend && npm run dev` (default Next port `3000`).
- Frontend checks: `cd frontend && npm run lint && npm run typecheck && npm run build`.
- Backend setup/run: `cd backend && python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt && python -m uvicorn app.main:app --port 8000`.
- Backend smoke/API docs: `http://localhost:8000/` and `http://localhost:8000/docs`.
- There are no checked-in test runners or test scripts; for backend changes, run focused import/API smoke tests plus the relevant frontend checks if UI behavior is affected.
- Do not start a second dev server on a port already owned by the user; stop agent-started servers before finishing.

## Frontend gotchas

- `frontend/AGENTS.md` is generated by `next dev` for Next 16 breaking-change guidance; do not delete it just to clean a diff.
- Before changing Next APIs or conventions, read the relevant local docs under `frontend/node_modules/next/dist/docs/` because this repo uses Next `16.3.2`.
- Keep `frontend/next.config.ts`'s `turbopack.root = path.resolve(__dirname, "..")` unless you are deliberately changing subdirectory app resolution.
- Tailwind is configured through `@tailwindcss/postcss` in `frontend/postcss.config.mjs`; there is no active `tailwind.config.*` in the Next app.
- `@/*` resolves to `frontend/src/*` via `frontend/tsconfig.json`.
- Visual direction is dark-first, operational, and route-led. Use color semantics consistently: blue = delivery/outbound, green = return/optimized/success, amber = attention, red = infeasible/problem.
- Avoid turning the UI into generic SaaS, eco-NGO, AI chatbot, or truck/leaf-icon branding; the core metaphor is two directions becoming one loop.

## Backend/API gotchas

- `/upload` validates CSV columns, stop type, and coordinates before returning parsed rows; `/optimize` accepts `OptimizationRequest.stops` directly and then clusters, routes, scores, and enriches.
- CSV schema lives in `data/demo_stops.csv`, `backend/app/main.py:REQUIRED_COLUMNS`, and `backend/app/models.py:Stop`; keep all three aligned.
- `cluster_stops` overwrites `cluster_id` using DBSCAN with `eps_km=3.0` and `min_samples=2`.
- `build_bidirectional_loop` optimizes delivery stops and return stops as separate nearest-neighbour + 2-opt segments, then concatenates them. It is not a persisted route, road-network route, capacity solver, or depot-closed loop unless you add that.
- `GEMINI_API_KEY` is optional. Without it, anomaly detection and summary generation fall back to deterministic heuristics/templates; never print the key value.
- Gemini anomaly calls are currently per-return-stop and sequential; do not put them on a new route-critical path without measuring latency.

## Deploy/config facts

- Frontend deploy target is Vercel with project root `frontend`; `frontend/vercel.json` only declares the Next framework.
- `netlify.toml` still points to `frontend/dist` from the old Vite shape; do not treat it as current Next deployment evidence without fixing it.
- Backend deploy target is Render via `render.yaml` (`rootDir: backend`, install from `requirements.txt`, start `uvicorn app.main:app --host 0.0.0.0 --port $PORT`).

## Hygiene

- Do not edit or commit generated/local artifacts: `node_modules/`, `.next/`, `.venv/`, `__pycache__/`, `*.pyc`, or `*.tsbuildinfo`.
- Do not commit or print `.env*` values. Backend secrets are server-only; the current frontend demo should run without secrets.
